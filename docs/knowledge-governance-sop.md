# 知识全生命周期治理 SOP（Knowledge Governance SOP）

> 项目代号：GKB · 关联：`scope-statement.md`（S5）/ `risk-log.md`（R01/R02/R06/R08）
> 覆盖四条主线：**入库 → 更新 → 过期淘汰 → 错误反馈闭环**。每条 SOP 配泳道流程图，明确「谁在何时做什么」。

## 0. 通用角色泳道说明

所有 SOP 共享以下泳道角色：

| 泳道 | 角色 | 职责 |
|---|---|---|
| 提交人 | 各事业部员工 | 提交/反馈知识 |
| 知识 Owner | 各事业部知识负责人 | 内容审校、质量把关 |
| PMO/治理组 | 平台治理组织 | 流程合规、跨部门协调 |
| 系统 | 平台自动化能力 | 校验、标记、降权、留痕 |

## 1. 知识入库 SOP

```mermaid
flowchart TD
    subgraph 提交人
        A[准备文档并填写元数据] --> B[提交入库]
    end
    subgraph 系统
        B --> C[格式校验 + 敏感词扫描]
        C -->|不通过| D[退回并说明原因]
        C -->|通过| E[切块 + 向量化]
        E --> F[赋密级 + 事业部标签]
    end
    subgraph Owner
        F --> G[内容质检]
        G -->|不合格| D
        G -->|合格| H[批准入库并生效]
    end
    subgraph 系统
        H --> I[发布至检索索引 + 审计留痕]
    end
```

- **质检要点**：来源明确、无过期内容、无涉密越级、格式合规。
- **SLA**：Owner 审校 ≤ 2 个工作日；未处理自动提醒。

## 2. 知识更新 SOP

```mermaid
flowchart TD
    subgraph 提交人
        A[提出更新/修订] --> B[基于原文档生成新版本]
    end
    subgraph 系统
        B --> C[版本号自增 + 记录变更说明]
        C --> D[旧版本标记为「待下线」]
    end
    subgraph Owner
        D --> E[审校新版本]
        E -->|通过| F[批准生效]
        E -->|不通过| G[退回修订]
    end
    subgraph 系统
        F --> H[新版本生效 + 旧版本归档可回溯]
        H --> I[通知引用方版本变更]
    end
```

- **版本规则**：`主版本.次版本`，重大变更升主版本，修订升次版本。
- **冲突处理**：同一主题多源矛盾时，由 Owner 仲裁并标记唯一「生效版本」（对应风险 R02）。

## 3. 知识过期淘汰 SOP

```mermaid
flowchart TD
    subgraph 系统
        A[定期扫描有效期/引用热度] --> B{触发淘汰条件?}
        B -->|到期| C[自动标记「待淘汰」并降权]
        B -->|低质量/零引用| C
    end
    subgraph Owner
        C --> D[复核是否保留]
        D -->|保留| E[续期 + 说明理由]
        D -->|淘汰| F[确认下线]
    end
    subgraph 系统
        E --> G[恢复权重]
        F --> H[移出检索索引 + 归档留痕]
        H --> I[通知订阅该主题的用户]
    end
```

- **淘汰条件**：超过有效期、长期零引用且无更新、被判定为过时/错误。
- **安全类/工艺类知识**：行业专项要求见 `industry-appendix.md`（如参数失效即冻结）。

## 4. 错误回答反馈闭环 SOP

> 直接对抗痛点 P3（幻觉），是「AI 回答效果」与「知识质量」的反馈回路。

```mermaid
flowchart TD
    subgraph 终端用户
        A[发现错误回答] --> B[提交反馈: 指出错误+期望]
    end
    subgraph 系统
        B --> C[自动登记台账 + 关联原回答与引用来源]
        C --> D[按密级路由至对应Owner]
    end
    subgraph Owner
        D --> E[复核: 知识错误还是模型问题]
        E -->|知识错误| F[修订/下线对应文档]
        E -->|模型问题| G[上报评估组, 调整策略]
    end
    subgraph 系统
        F --> H[重新索引 + 回归验证]
        G --> I[记录模型策略变更]
        H --> J[通知反馈用户闭环结果]
        I --> J
    end
```

- **闭环 KPI**：闭环率 ≥ 95%（对应 S7）。
- **台账字段**：反馈内容、来源回答、根因分类、处理动作、处理人、闭环时间。
- **根因分类**：知识过期 / 知识缺失 / 知识错误 / 检索偏差 / 模型幻觉——用于反向驱动治理（对应风险 R08）。

## 5. 治理组织与运行节奏

| 机制 | 频率 | 内容 |
|---|---|---|
| 知识 Owner 例会 | 双周 | 质量问题、积压审校、淘汰复核 |
| 治理数据看板 | 周 | 入库量、更新量、淘汰量、闭环率、幻觉率 |
| 季度治理回顾 | 季 | 治理策略调整、Owner 责任重分配、行业细则启用评估 |
